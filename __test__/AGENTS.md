# Shared tests and backend coverage

Discover focused test paths with `rg --files __test__` before invoking a runner, then check its executed-file summary: both runners can ignore nonexistent path filters when another filter matches.

Read `../dev/cross-language.md` §Parity before changing implementation selection; it owns the required native loader order and reuse of TypeScript tests for Rust and WebAssembly.

- Reuse test bodies and independent expected results. A separately generated conformance corpus is additional evidence, never evidence that the TypeScript suite ran against Rust. Record the selected implementation and nonzero execution for each backend. Keep JavaScript host-only checks explicit; never count TypeScript fallback or an unsupported case as Rust execution.
- Keep shared state out of setup entry modules: browser runners add cache keys to those URLs, so import the state owner from a setup wrapper and require per-case execution counts from the same owner.
- Account for every behavioral suite before closing backend reuse. Split mixed suites at their actual contract boundary: a JavaScript-only case must not exclude neighboring portable cases. Name the missing capability and its owning test; a file name, private import or inconvenient adapter is not an exclusion reason. Keep unported cases open in the live plan.
- Mark JavaScript-only contracts beside each case, with the host behavior or Rust type boundary that makes it inapplicable; keep them running in the TypeScript lane. A missing Rust binding must fail, never become an exclusion.
- Require execution evidence for every registered shared suite, not merely a nonzero total or one matching file. Define the selected files once, use that list for discovery and compare every member with the observed executions; filtering out one suite must fail even when the remaining tests pass.
- In a runtime/version matrix, pass the discovered executable and arguments through supervision and assert the actual version inside each test worker. A lane label or version-manager environment variable does not prove which executable a launcher resolved; reuse the host registry rather than reconstructing its command from PATH.
- Tests that create an independent repository must isolate repository-specific environment values and restore the caller's values in `finally`; CI commit IDs belong to the outer checkout, not the fixture. Reproduce with the real CI environment before changing production routing.
- Keep mutable module caches inside each supervised runner's scratch scope; concurrent hosts must neither clear another run's cache nor leave theirs behind after interruption.
- Before adding a rejection expectation, apply `../dev/interface.md` §Rules' consumer-harm check. A narrower type or the current implementation is not evidence that the rejected call should fail.
- Entropy observations require successful generation: a returned error must fail the observer, even when no insecure source was observed.
- Exercise automatic native loading with the forced-transport variable absent, as well as each forced route. Use real libraries: remove the primary artifact in an isolated directory to reach fallback, and use an uncached missing path for total failure. Require an execution result from the loading controls; a skipped helper must not satisfy the lane. Disabling fallback must fail the missing-primary control. Reuse `scripts/rust-conform-matrix.ts` rather than creating another host registry.
- Execute processed WebAssembly, never raw compiler output, for acceptance. Read `../dev/cross-language.md` §Distribution and dependencies and `../bench/methods.md` §Compiler and WebAssembly optimization before changing its pipeline or interpreting its measurements.

Keep transport, serialization and caller ownership checks beside shared semantic tests; none substitutes for the others. Caller-buffer cases must execute the target implementation's writer and return its storage on failure as well as success; copying decoded bytes in the host proves only the host copy. Extend the nearest harness and preserve its interruption cleanup and feedback budget.
