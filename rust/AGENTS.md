# rust/ — Rust crate and development bridges

Rules for editing Rust code. Root `AGENTS.md` applies too. `dev/cross-language.md` owns the full rules; read §Parity and §Rust call sites before changing behavior.

- Shared behavior changes MUST land in BOTH TypeScript and Rust, with their shared contract cases (`scripts/rust-conform.ts`). Rust-only dependency features must preserve that behavior in every selection. Agreement between implementations proves nothing: expected results come from README §Guarantees, `docs/design.md`, retained fixtures and reference vectors.
- Preserve issued IDs: wire constants, alphabets and hash order are frozen (`docs/design.md`).
- Before changing migration or sentinel priority, read `../docs/api.md` §Reading original slugs during migration and `../__test__/legacy-mask-probe.ts`: a legacy sentinel alias can also be a current masked ID. Candidate reads retain both; first-result reads prefer the sentinel.
- For proof work, load the `rust-proofs` skill and extend `proofs/` against the production bodies. Cover success, rejection and state preservation over symbolic inputs; keep bounds, caller assumptions and unchecked effects beside each theorem. Run `bun scripts/check-rust-proofs.ts` after changing any body it covers, not only the bit codec; buffer admission and payload partitioning also require `bun scripts/check-rust-verus.ts`.
- For omitted-harness controls, Kani can reject an exact name before emitting JSON. Require its explicit missing-name diagnostic and nonzero exit; do not mislabel that selection failure as a solver counterexample or rerun it merely to obtain a report.
- When changing the fixed-size bit codec, run `bun scripts/check-rust-proofs.ts`; its Kani harnesses import the production kernels and compare them with an independent wire oracle. The command checks Cargo's locked graph separately: Kani does not accept Cargo's `--locked` flag. Preserve named-harness coverage and semantic counterexamples. These proofs do not replace native, allocation, caller-buffer or optimized WebAssembly checks.
- Before changing a private kernel, trace its ordinary callers and `#[path]` imports in `bridge/` and `proofs/`. Update their adapters to exercise the changed production path; do not retain obsolete preprocessing or suppress unused-helper warnings to clear the gate. Check workspace Clippy as well as package tests: importing the whole source gives each adapter its own use graph.
- Before replacing source-imported types with public crate imports, inspect the methods their callers use: crate-private methods require the original local type graph. Keep those source imports rather than widening the public API for a prover.
- When changing buffer admission, run `bun scripts/check-rust-verus.ts`: success must accept every fitting UUID and reject overflow or insufficient capacity. Verus checks the production decision; native buffer mutations still establish writer and failure-atomicity coverage.
- Before rejecting a native generator, name the call and published promise it violates (`../dev/interface.md` §Generation and codecs). Simple Bun defaults use Bun directly; different counters, shared state or logical clock advancement alone are not parity defects. Created generators must provide their requested controls.
- Add a Rust dependency only after the comparison in `dev/cross-language.md` §Distribution and dependencies.
- Keep `uuid-interop` opt-in; defaults must not compile `uuid`. Preserve secure default generation with OS-seeded ChaCha12. Disable dependency defaults and enable only features reached by required calls on the selected target; inspect the resolved normal graph, not the manifest alone, before claiming a dependency or capability is absent.
- Dependency ownership, algorithm choice and interoperability are separate decisions. Read `../bench/AGENTS.md` §Choose the decision before replacement experiments; a slower substitute cannot establish that owning upstream code loses. Copy only needed kernels and preserve their license and source revision. On every `uuid` dependency update, review its parser/formatter changes against the pinned copy, port relevant fixes and rerun both feature selections; never sync unrelated upstream machinery.
- Judge unsafe code by its invariants and callers, whether local or in a dependency; “no local unsafe” proves origin, not memory safety. Keep unsafe denied except the scoped ASCII-to-text formatter conversion; document complete initialization and ASCII-only output at that block. Compile out the owned text backend when `uuid-interop` delegates to upstream, rather than relying on the linker to remove a duplicate.
- After changing a crate's dependencies, find every repository Cargo workspace that uses it through a path dependency and refresh each affected lockfile without unrelated upgrades. Separate workspaces record their own dependency graphs; `rust/Cargo.lock` alone is insufficient. Before committing, run `bun run bench:competitors:rust:check` as well as the affected product checks so every normal `--locked` consumer still resolves.
- Before changing features, generic boundaries or inlining for unused-code removal, read `../dev/cross-language.md` §Rust optimization. Inspect a real consumer artifact; source organization and binary size alone do not prove removal.
- `bridge/` serves development only: never published, no public ABI. Before changing its loaders or shared tests, read `../__test__/AGENTS.md`; it owns automatic/forced selection and backend coverage checks. Browsers load the generated wasm-bindgen boundary. Panic handling cannot contain allocation aborts or WebAssembly traps, so keep real host transport checks.
- FFI output sizing must never repeat stateful dispatch: retain the prepared response only until the synchronous caller copies it, and verify that buffer growth neither advances generators twice nor allocates duplicate handles.
- Verify with `bun run check:rust`, then `scripts/rust-wasm.ts` under `UUID_SLUG_RUST_PROFILE=debug` and `release`. For focused Cargo checks, run `test --doc` separately from `test --lib` or other target selectors; Cargo rejects combining them.
- Browser Wasm feature checks select the library; native-only benchmark executables are checked by `check:rust`. Do not add empty Wasm entry points to make an unsupported executable target compile.
- Run WebAssembly checks on optimized binaries as required by `../dev/cross-language.md` §Distribution and dependencies; compiler output alone is not the final artifact.
- Reuse `scripts/rust-toolchain.ts` and `scripts/command.ts` for custom Cargo feature/profile matrices. Bash 3.2 rejects empty argument arrays under `set -u`, so a shell loop can stop before Cargo runs.
- Direct `rustc` consumer probes must use the Cargo-reported library plus `<target>/<profile>/deps` in `-L dependency`. Cargo can report a top-level rlib, so its parent directory alone does not resolve dependencies. Require a valid call to compile and the invalid call to fail for its intended diagnostic; a missing crate or mismatched toolchain proves nothing about the API.
- Install additional verification toolchains with `rustup toolchain install --no-self-update`; checking compiler compatibility must not also update the shared rustup manager.
- Show extra Cargo dependencies beside the examples that need them. Verify those examples in a separate app with only the documented dependencies: doctests inherit this crate's dependencies and can hide missing setup.
- Before crate publication, review the packaged README as both the crates.io landing page and the crate-level API documentation. Give registry installation first, state the manifest's minimum Rust version, and verify generated rustdoc as well as doctests; doctests do not detect broken documentation links.
- Review callback obligations and feature availability on each generated public item page, not only in source comments or the crate overview. Callers entering through an item link must know how to use it safely; use rustdoc's cfg-derived feature badges rather than another feature inventory.
