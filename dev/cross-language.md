# TypeScript and Rust contracts

Keep the same IDs readable in TypeScript and Rust, with matching validation, errors, and buffer ownership rules.

## Parity

Every feature, fix, and contract change must update both implementations and their shared contract cases. Any semantic exception requires the maintainer's explicit ruling before shipping.

README §Guarantees owns consumer promises; [design.md](../docs/design.md) owns masking and wire semantics. Neither implementation becomes correct merely by agreeing with the other: expected results must come from those contracts, retained producer fixtures, reference vectors, or independently checkable properties. Preserve issued identifiers when changing either implementation.

Identical deterministic inputs must produce identical bytes, text, keys, and decoded candidates. Parity includes accepted and rejected inputs, defaults, error conditions, sentinel priority, key order, migration controls, timestamp windows, cancellation, and ownership of returned data. Sentinel names and UUIDs are unique within one codec; both languages report either duplicate as `invalid_sentinel` without relabeling malformed UUID text or UUID-version failures. Both languages always write registered sentinels as plain slugs without masking, so the masked timestamp limit does not apply to them. Every decoder must accept every value that a supported matching encoder can produce. Options may add accepted forms; they must not remove existing ones. Forms no supported encoder produces are invalid. Generated identifiers must meet the same promises; random draws, exact sequence positions, scheduling, and allocation strategy need not match.

Simple Bun UUIDv7 text and base64url calls delegate directly to Bun, including its shared counter and logical timestamp advancement. Created generators provide the requested ordering, rollback and payload layout controls. Parity preserves caller promises and all UUID bits; it does not require simple defaults to use a created generator's counter width or state sharing.

Keep verbs and parameter meanings recognizable across languages. Rust may use ownership, typed errors and `Result` instead of JavaScript conventions. Such differences must not silently change the accepted domain or result semantics. In particular, a lazy result must not expose partial candidates where the existing operation reports an error for the whole call.

TypeScript accepts standard JavaScript host forms through `at`, including exact epoch nanoseconds. Rust accepts `SystemTime` for current and supplied-time generation, while fractional Unix milliseconds remain available for numeric interop. Both store the containing Unix millisecond and quantize the remaining fraction when the generator's payload layout assigns fraction bits. Supplied-time generation joins a created generator's sequence state in both languages.

TypeScript uses directional text/binary names because raw byte containers require validation and may target caller storage. It accepts an exact `ArrayBuffer` or a `DataView`'s exact 16-byte range as borrowed input. Rust uses idiomatic `Uuid` operations because its fixed UUID type already owns that validation; `&[u8]` already provides the same range semantics. Both accept mixed-case canonical or compact text, case-insensitive UUID URNs, and brace-wrapped canonical text. Their default text output is lowercase and hyphenated, and their byte domain is identical. Wrappers cannot nest or contain compact text.

Run shared cases through each implementation from its first increment; check nonzero execution per adapter, because an aggregate pass can hide one that ran nothing. Keep native ownership and callback checks; map JS UTF-16 explicitly rather than pretending Rust strings cover its full domain.

Reuse the TypeScript test suite against native Rust and WebAssembly rather than maintaining a smaller parallel behavioral suite. Native test loading prefers Bun FFI with Node-API fallback, and Node-API with experimental Node FFI fallback on Node. Keep forced transport checks and report the selected backend; neither a fallback nor an unsupported test may silently count as Rust execution. JavaScript-only host behavior and native ownership still need their own checks.

## Rust call sites

Use `UuidV7MaskingCodec::parse_uuid(&str)` for mixed UUID text, plain slugs and this codec's masked slugs. Registered sentinels win first; ambiguous base64url tries masks in configured order before accepting canonical plain bytes. Callback errors stop decoding. Keep `Uuid::from_plain_uuid_slug` and `masked_slug_to_uuid` for known source meanings; a parsed Rust `Uuid` owns only its bytes and does not retain the codec or its keys.

Keyless parsing accepts `KeylessUuidText`: ordinary `str` and `String`, typed plain slugs, and references, `Box`, `Rc`, `Arc` or `Cow` around accepted inputs. Seal this trait so a typed masked slug cannot implicitly enter a keyless decoder through its `Deref<str>` implementation. Custom wrappers pass an explicit text view; `.as_str()` deliberately erases provenance. Raw base64url text can still be ambiguous. Keep parsing nongeneric behind thin borrowed wrappers so input types add no parsing, allocation or parser duplication. A detached generic function fixes its input type on use; use an explicit `fn(&str) -> Result<Uuid, Error>` when one function value must accept different deref-coercible string containers.

Use validated `Uuid` values between operations; parse text once rather than at each codec call. Use `From` conversions between `Uuid`, `uuid::Uuid` and `[u8; 16]` without text or allocation. `TryFrom<&[u8]>` requires exactly 16 bytes; explicit-offset reads select a UUID in a larger buffer. Preserve every bit without imposing version or variant validation. TypeScript interoperability uses its existing strings and standard byte containers rather than library-specific adapters. Both languages generate UUIDv4 and UUIDv7 only. Generic parsing, version inspection, and plain conversion preserve other UUID versions without version-specific APIs. Do not add generation, constants, bounds, fields, guards, or helpers for another version unless the maintainer reopens that boundary for concrete demand.

Any high-resolution generation mode must expose the same fraction width and counter layout in both languages. Fractional Unix milliseconds can carry UUIDv7's 12 fraction bits near the current epoch; they cannot preserve arbitrary nanoseconds. Runtime clock selection may differ, but one generator configuration must keep one wire layout.

TypeScript accepts `epochNanoseconds` as `bigint` because Temporal and timestamp protocols already provide that form and caller-side conversion would discard useful fraction bits. Its numeric Unix-millisecond form remains the shorter path when a `number` already identifies the needed bucket. Rust accepts exact supplied time as `SystemTime`. Its fractional Unix-millisecond method remains a narrow bridge for numeric interop rather than the primary Rust call.

Native and WASI Rust use `SystemTime` for configured fraction bits. Browser WebAssembly uses `Date.now()` and therefore starts configured fractions at zero until logical ordering advances them. Callers that need measured browser precision can pass fractional Unix milliseconds through `generate_uuid_v7_with_random_fill`; the callback also owns secure entropy on that path.

`scripts/rust-conform.ts` executes the shared wire, acceptance, rejection, ordering, and error cases through both implementations. Its exact-time sequence cases cross a fraction-bucket boundary and the maximum UUIDv7 timestamp so the mapping above cannot hide precision or range drift.

TypeScript additionally exports `isUuidSlugError` because JavaScript values can cross realms or load from duplicate package copies. Rust exposes `ErrorCode` as the typed classification so adding a diagnostic source does not change how callers match a failure; bridges serialize `ErrorCode::as_str()`. Both implementations use stable codes for control flow and case-specific messages for diagnostics. Messages can add detail; callers must not parse them. Underlying runtime and callback failures stay available through `cause` in TypeScript and `source()` in Rust.

Generators own mutable sequence state; codecs own immutable keys. Both languages require callers to select private key material or the published mask explicitly. Keeping generation separate allows shared codecs without a hidden generator lock. Rust `UuidV7MaskingCodec::new(mask)` returns the default codec directly: an explicit valid mask cannot invalidate the default range or empty sentinel list. `from_options(options)` validates configured ranges and sentinels once and returns `Result`. Default generators use platform entropy; custom separately named TypeScript calls and Rust `_with` callbacks must fill the entire destination or fail. Pass `fill_os_random_bytes` to caller-buffer operations for the same platform source. Invalid destination ranges draw no entropy. `UuidSlugAlphabet::uuid_bytes_to_plain_slug` accepts a 16-byte array and cannot receive another payload size. It preserves every 16-byte value. `plain_slug_to_uuid_bytes` returns a 16-byte array or an error for non-canonical input. UUID version and variant checks belong to UUID guards. `plain_slug_to_uuid_bytes_into`, UUID text and slug parsing validate the complete identifier before writing; all fixed-size decoding, parsing and generation commit caller storage only on success.

Async mask derivation returns an opaque `Send` future and a separate public `UuidV7MaskDerivationCancellation` handle. Callers can schedule and cancel work without depending on the derivation state's fields, layout, or incidental auto-traits.

## Filesystem-safe output

Support lowercase filesystem-safe representations for both plain and masked identifiers in both languages. Preserve existing encodings and key material. Lowercase output avoids distinctions lost on case-insensitive filesystems; it does not make arbitrary surrounding paths safe.

Plain slugs already use 26 base32hex characters for 128 bits. A lossless base32hex representation of the existing 132-bit masked payload needs 27 characters, with three zero padding bits. Reject nonzero padding on ordinary decoding. Preserve the entire masked payload, including the four tag bits outside its 16-byte block; re-encoding only that block would lose information.

This is an alternate spelling, not a new masking scheme; retain the 16-bit check and timestamp bound. Safe sentinels remain raw UUID slugs: 26 base32hex characters, readable by the plain-slug decoder. Padding them to 27 adds a spelling that the plain-slug decoder rejects, with no identity benefit. Their length cannot collide with 27-character masked output. Keep old base64url reads and defaults. Masking has no chronological ordering.

## Distribution and dependencies

Publish one npm package and one Rust crate. Keep JavaScript chunks internal and Rust targets under one release identity. Add prebuilt Rust artifacts only when a measured consumer need justifies them. Do not publish a CLI. The library calls already serve application conversion and generation without process startup, shell parsing, or a second distribution surface; reconsider a CLI only after concrete shell, migration, or debugging demand identifies a job the libraries do not serve. Publish `src` as executable package code for Bun and the opt-in `development` condition; source-map resolution is a second use, not its reason to exist. Prefer source for a runtime that normally loads TypeScript. Use compiled output only when a packed consumer proves that the runtime's default resolver cannot load this source graph. Do not shift resolution cost to consumers through a flag or false `.js` specifiers. Every relative source import names its real `.ts` file; the compiler rewrites emitted imports to `.js`. Condition-selected runtime adapters keep one public source entry while using each host's capabilities. The optimized build must remain executable in Bun as well as Deno, browsers, and Node-compatible hosts. When Bun loads that compiled graph, `#runtime` must still select its TypeScript adapter and native primitives; normal source selection does not waive this path. Keep one compiled implementation graph; resolve its private `#runtime` import to Bun source, the compiled portable adapter for Deno, or Node native code. Deno refuses TypeScript inside npm packages, so it loads compiled output. Deno also activates the `node` condition, so its condition must come first. Ship source maps whose inputs resolve inside the package. Cloudflare Workers use the portable compiled graph over Web Crypto, with or without `nodejs_compat`. Run `bun scripts/check-artifact.ts --edge` to check a bundled packed consumer inside a local workerd request; this does not establish deployed entropy or clock behavior.

### JavaScript packaging

Keep ESM modules unbundled and `sideEffects: false`. This lets consumers remove features they do not import. Every shipped module must therefore remain free of required import-time effects. Each private file boundary must enable independent loading, removal, runtime selection, or an externally exercised implementation seam. Merge a leaf into its sole production importer when none applies; do not pre-bundle unrelated modules merely to lower the archive's file count. Keep a declaration private unless a package contract, production import, tool protocol, or independently exercised test seam requires module access. Tests must use the owning interface after logic moves into its sole production consumer; remove the obsolete export and direct test import. Before deleting a moved file, compare its implementation and comments with the destination, account for every difference, and verify every former consumer now reaches the destination. Probe stable optional capabilities once in the smallest module that owns them; never repeat the probe per call. Defer an allocation when imports that do not need it share that module.

Use `/*#__PURE__*/` only on removable construction. Annotate nested calls separately because a bundler may still evaluate arguments. Use `/*#__NO_SIDE_EFFECTS__*/` only on functions that are safe to discard for every accepted runtime input. Apply that rule to public and internal functions; visibility does not prove that downstream optimizers can infer it. Property access on untrusted objects can run proxy traps or getters and is not side-effect-free. Never apply either promise to generation, caller callbacks, clock or entropy reads, mutable state, or caller-owned output.

Preserve optimizer annotations in emitted JavaScript. Keep whitespace when removing it strips them; retain compression and ordinary identifier mangling. Keep function and class names in both compression and mangling so stack frames remain useful. Do not mangle properties without a private, reserved namespace proven safe across every consumer bundler.

Ship JavaScript and declaration maps, but exclude embedded source text because the package already ships `src/`. Keep the JavaScript target explicit and fail on build warnings so runtime support cannot drift through manifest or tool defaults. The packed-artifact check must reject missing map inputs, embedded sources, machine paths, and lost source-owned optimizer annotations.

The JavaScript target floor defines the unguarded baseline, not a ban on newer platform APIs. A newer standard or host capability may be selected when it measurably reduces runtime or resource work, provided module-load detection chooses it once, an older-runtime fallback preserves behavior, and both branches run in their actual runtime lanes. Do not add a conditional branch when the newer primitive has no consumer-path advantage.

Keep the public npm package TypeScript/JavaScript-only, with no runtime dependencies or native payloads. Keep the Rust crate installable from this Git repository and crates.io. Maintainer policy requires matching Rust/TypeScript versions and common CPU architecture support from the first Rust release, including WebAssembly. Preserve portable behavior under architecture-specific tuning. Support x86-64 and Arm64 on Linux, macOS and Windows with native execution; compile-check i686 and ARMv7 Linux, and execute `wasm32-unknown-unknown` in every browser engine selected by the check workflow. Execute the unit tests on `wasm32-wasip1` and `wasm32-wasip2`, whose hosts supply entropy and clocks through WASI imports instead of the browser's. Ship no prebuilt WASM: consumers compile the crate for their own host, and a published module would fix an ABI nobody has asked for. The workflow owns the concrete engines, runner labels, and target triples so this contract does not copy a volatile matrix. Build and test natively in GitHub CI from the first Rust increment; cross-compilation alone does not validate runtime behavior. Report any target lacking native execution rather than implying it ran. Keep `std` optional. Retain a Rust dependency when it does the best reasonable job; replace it only for demonstrated performance or resource gains without correctness, capability or quality loss. Challenge `uuid` first, then `data-encoding`, on complete consumer calls. Compare failure behavior, supported targets, build costs, licensing and maintenance; neither fewer dependencies nor implementation convenience decides the result.

Keep Rust benchmark drivers out of the published crate; retain the library, license, consumer examples and fixtures needed to test its extracted sources. Verify Cargo's normalized archive, since a workspace file list does not prove what consumers receive.

Rust's `fast-rng` reuses OS-seeded ChaCha12 state to avoid an OS call for every UUID. Each thread owns its state, so generation needs no global lock. Require a new seed before exceeding 64 KB of output and after a native process-ID change; seed failure must return an error, never reuse an exhausted or inherited stream. `rand`'s thread RNG cannot provide that error contract because it panics on seed failure. Keep `fill_os_random_bytes` direct and conversion-only builds free of both dependencies. Reconsider this dependency if complete calls or other targets lose on cost.

Use Rust features for host capabilities. Defaults enable `std` and `fast-rng`; `fast-rng` requires `std` and `os-rng` for per-thread state. Keep `os-rng` independently usable without `std` on supported entropy targets. `wasm-js` enables `std`, OS-source selection and JavaScript clock integration. Without defaults, keep conversions, masking, migration, derivation and explicit Unix-time generation on `core` and `alloc`; callers supply entropy. Require allocation and pointer-width/8-bit atomics for shared masks and cancellation. Gate `SystemTime` methods and thread-local conveniences behind `std` rather than retaining unavailable host operations in reduced builds.

### Rust optimization

Design Rust calls so consumers compile and retain only the capabilities their application needs; verify compilation cost, linked code and runtime work separately.

| Concern | TypeScript | Rust |
| --- | --- | --- |
| What identifies unused work | A bundler follows ESM imports and uses side-effect information. | The compiler and linker follow reachable calls and data in the consumer program. A public method is not automatically a retained binary export. |
| Optional dependencies | This package has no runtime dependencies; named imports select removable code. | Cargo features exclude optional dependencies and unavailable host code before compilation. Link-time removal alone does not avoid compiling enabled dependencies. |
| Cross-module optimization | Preserve ESM boundaries and valid purity annotations in shipped JavaScript. | Keep selected values visible across call boundaries; small generic or inline wrappers can help. Rust module paths are organization, not equivalents of npm subpaths or purity annotations. |
| Final artifact | Execute each consumer bundle under independent bundlers. | Execute and inspect native consumer binaries and optimized WASM, with ordinary release and ThinLTO treated separately. Explicit WASM exports remain reachable. |

Apply these choices to the crate:

- Keep generation, plain conversion and keyed masking separate. A v4 call must not construct a v7 generator or codec; a v7 call must not calculate a slug the caller did not request. This also lets either version disappear when only the other is used.
- Use host-capability features as described above, rather than one switch per method or UUID version. Features are additive across the dependency graph: an application's disabled defaults cannot cancel features enabled by another dependency. Check the resolved graph as well as the binary.
- Carry validated values across calls. `Uuid` owns `[u8; 16]`; `From` interoperability transfers bytes, and formatting writes through the caller's formatter. Conversion does not need a string round trip, another parse or an inspection object containing unused fields. Caller-buffer methods preserve output ownership and commit only after successful validation.
- Keep input-type wrappers thin. The sealed `KeylessUuidText` trait prevents known masked inputs from entering keyless parsing; its generic entry points forward to shared nongeneric parsers. Specialize where a selected value removes real work, not by duplicating an entire parser for each string container.
- Keep alphabet data immutable and initialization-free. Fixed ASCII tables avoid alphabet construction; a shared runtime alphabet selector can still retain both tables, so inspect real consumers before claiming removal.
- Separate a selected algorithm from shared work that does not depend on that selection. Plain decoding passes the selected alphabet into a boundary specialized for the two wire layouts; caller-buffer decoding shares its checked copy after that work. Thin writer and reader forwarding methods expose a caller's constant alphabet across the library boundary. The fixed-size encoder also needs inline visibility: measured single-alphabet native release and optimized WASM consumers discard the other table, while the both-alphabet control retains both. Recheck these consumers after backend or boundary changes; complete-call speed remains a separate release requirement.
- Use `#[inline]` only where consumer optimization needs visibility, then measure the whole call and artifact. It is a hint, not a removal guarantee; wider inlining can increase code size and compilation work. Do not require LTO to hide avoidable coupling in ordinary release builds, or replace runtime configuration with extra public types solely for a smaller probe.
- Keep mutable state with the operation that needs it. Generators own their sequence, codecs own immutable keys, and default fast entropy is thread-local. Parsing and formatting must not initialize those generators. Custom mask callbacks remain an explicit capability; replacing them with static dispatch must not remove caller functionality.

The [linked-consumer evidence](../bench/decisions.md#rust-linked-consumers-and-interoperability) records native v4/v7 and alphabet removal, optimized browser execution and retained binding overhead. Native symbols do not establish WASM code removal; WASM imports identify host dependencies, not unused pure code. Recheck after changes to call boundaries, features, dependencies, compiler, target or optimizer. Smaller files alone prove neither correct removal nor preserved speed, entropy or failures.

Unused-code removal must work in every direction: v4-only, v7-only, parsing, formatting, individual alphabets, encoding, decoding and masking consumers must retain only the capabilities they use. Verify default and reduced-feature builds separately, with ordinary release linking before optional ThinLTO. Inspect final native and WebAssembly consumer artifacts with positive controls for omitted capabilities; compiler dependencies, linked code and required host imports are different costs. A retained capability must have a consumer requirement, not merely share a module with the requested operation.

Optimize WebAssembly binaries before comparing sizes or using execution results to verify them. Use the same optimizer and settings for baseline and candidate, and run the optimized files in the required browser and WASI hosts for each profile. Keep unoptimized output for diagnosis only; it does not prove the final artifact's size or behavior.

Verify every supported build type and target, not just the default release configuration. Cover debug and release profiles, product libraries, development bridges, examples, unit tests, doctests, and benchmark compilation with each distinct supported feature selection. Run every locally executable combination and retain the full supported target matrix in CI. Report compile-only and unexecuted combinations explicitly; a configured CI job is not execution evidence. Use `bun run check:rust` for native profiles. Run `scripts/rust-wasm.ts` with `UUID_SLUG_RUST_PROFILE=debug` and `UUID_SLUG_RUST_PROFILE=release`; each profile must execute the same browser-engine matrix and both WASI targets.

Verify TypeScript functionality on every supported Node major and on the latest Bun and Deno. Derive Node majors from the published release index and the package's engine floor; include the exact floor and keep newest Node unpinned. Execute shared contracts and consumer calls without a test runner in the target engine, so the runner's narrower support range cannot remove package coverage. Also run the ordinary suite wherever its installed tooling supports the engine. Preserve real runtime adapter coverage when changing test runners; a faster Bun suite cannot establish Node or browser behavior. Replace a runner only after matched defect-detection and performance measurements, retaining the same consumer contracts.

### Runtime floors

A floor is the oldest release we promise. Each floor MUST run the package-only consumer probe in CI; a floor nobody tests is a guess that rots. Pick the oldest release that passes, unless every older one fails for a reason outside this package or supporting it would cost newer runtimes work.

| Runtime | Floor | Why this release |
| --- | --- | --- |
| Node | `>=20` supported; works from 16.20 | `engines.node` and its CI matrix promise 20. 16.20 and 18 pass the probe; docs may say "works from 16" only while a 16.20 lane passes. |
| Bun | `>=1.0.8` | Bun 1.0.0–1.0.7 run a `setImmediate` chain without ever firing timers, so `yieldToHost` in `src/mask.ts` cannot deliver an abort to async mask derivation. Everything else passes there, so the README badge may say `>=1.0`. Supporting them needs a version-sniffed yield path for builds replaced within weeks. |
| Deno | `>=1.29` | Oldest release CI can test: 1.28 ignores `NPM_CONFIG_REGISTRY`, so the probe cannot serve it an unpublished build; 1.25–1.27 need `--unstable` for `npm:`. Deno 1.x loads its Node layer from `deno.land/std` at run time, so a deno.land outage fails the lane; the probe retries once. |
| Browsers, workers | not declared | Compiled output targets ES2022 (class and private fields, `Object.hasOwn`, error `cause`). No old engine has run the probe. |

The `runtimes` CI matrix runs the Node engines floor. `bun scripts/floor-probe.ts` (CI job `floors`) covers the rest: it reads the Bun and Deno floors from `package.json` `engines`, adds Node 16.20, downloads those exact releases and runs `__test__/consumer-probe.ts` against a real install: a `node_modules` directory for Node and Bun, `npm:` from a local registry for Deno. Do not use `scripts/runtime-probe.ts` for floors: it imports rival libraries through `bench/candidates`, and they fail on old runtimes before the package runs. Raise a floor only when its lane fails for a reason a fallback cannot fix without slowing current runtimes; record that reason in this table.

Inspect the product's resolved normal dependencies separately from workspace development dependencies. Check disabled defaults and each optional feature: workspace feature unification can hide missing dependencies. Native profiling constrains current call costs; it does not establish that one encoder is fastest on every architecture or that platform randomness is trustworthy under every host condition.

Compare encoder changes with both caller storage and owned strings, varying dependency features. The earlier UUID-sized comparison favored a separate base64 encoder for caller storage, but its default features reversed the decoding advantage and owned-string differences were much smaller. Both rejected the tested padding aliases. This does not justify adding a second generic dependency; compare the shared fixed-size codec on complete calls instead.

Share hash primitives without forcing continuation overhead onto synchronous calls; a Future alone does not yield to host tasks. Node, Bun and Deno native bridges serve development only, remain unpublished, and stay outside npm. They do not create a supported public ABI.

Maintain native interop as one declarative research matrix that discovers supported installed Node, Bun and Deno hosts, then gives conformance and profiling the same lanes. Every lane must identify its actual Node-API or FFI transport and produce nonzero results from the common request corpus. Measurements describe that machine and revision; use them to improve each adapter and preserve the matrix unless the maintainer explicitly changes its research scope.
